Defining Functions
So far:
funName x1 x2 ... xN = expr
• x1 x2 ... xN are variables.
Now:
funName pat1 pat2 ... patN = expr
• pat1 pat2 ... patN are patterns.
• Definition of patterns on VO 3 - Slides 10/11
• Patterns allow us to define functions depending on the structure of the input.
• Input parameters then get matched against these patterns to decide which
function definition is applicable.
• Pattern matching allows us to define multiple right hand sides for the same function.
Example: 3example_pattern-matching.hs

Exercise 3.1: Possible Solutions: startsWith
Response to the question: the empty list doesn’t start with anything, so an empty list
should always return False.
startsWith :: List -> Integer -> Bool
startsWith Empty _ = False
startsWith (Cons number _) toMatch = number == toMatch

Exercise 3.1: Possible Solutions: replaceFirst
Response to the question: if there is no first element to replace, nothing will be
replaced, so just return the empty list.
replaceFirst :: List -> Integer -> List
replaceFirst empty@Empty _ = empty
replaceFirst (Cons _ rest) number = Cons number rest
Bonus question: what is the difference in the second line between empty and Empty?
Solution: Empty is the constructor of the empty list, it creates a new List type. But
empty is the matched empty list, that is supplied to the method, so no new list is
created, but the old empty one is just returned.
