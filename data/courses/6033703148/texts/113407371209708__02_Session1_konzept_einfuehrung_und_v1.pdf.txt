Aufgabenstellung Übersicht
(Details siehe OLAT)
• IoT-basiertes Raumklimamonitoring​
• Einsatz von Arduino und Sensoren zur Raumklimamessung​
• Sensoren messen Luftfeuchtigkeit, Temperatur, Luftqualität
• Arduino stellt Messdaten zur Bluetooth LE Übertragung bereit
• steuert Leuchtdiode, um Grenzwertüberschreitung zu signalisieren​
• steuert LCD Display Anzeige (momentane Messwerte, Grenzwertüberschreitungen,
hilfreiche Raumklimatipps)
• Minirechner (Raspberry Pi) ​
• Daten via Bluetooth LE von Arduinos empfangen
• Grenzwertüberschreitungen feststellen und Information auf Arduino übertragen​
• Daten auf Speicherkriterien laut Datenschutz prüfen und zulässige Messungen persistent
zwischenspeichern
• Gespeicherte Daten in konfigurierten Intervallen über eine REST-Schnittstelle an ein
zentrales Backend übertragen​
• Zentrales Backend zur Speicherung, Analyse und Auswertung der
Raumklimadaten und Darstellung in Webanwendung​

PS Software Engineering I Sommersemester 2026 Page 21
Softwarekonzept – Use Case Diagramm
• Fragestellungen, die Sie in Ihrem Konzept unbedingt
beachten sollten und teilweise direkt aus der Aufgabenstellung
herauszulesen sind:
• Wer darf welche Messdaten einsehen?
• Welche User sehen welche Grenzwertüberschreitungen und in welcher
Form?
• Welche User gibt es im System und wie stehen sie zueinander?
• Wie funktioniert die Geräte-Administration und wer hat Zugriff darauf?
• etc.
• Beschreiben Sie Akteure und Benutzer-Rollen kurz und prägnant
• Achten Sie darauf, dass das Use Case Diagramm im Einklang mit
allen anderen Inhalten des Softwarekonzeptes stehen (z.B. Use
Cases vs. GUI Prototyp)
PS Software Engineering I Sommersemester 2026 Page 22
Softwarekonzept – Use Case Beschreibungen
• Formulieren Sie detaillierter Use Case Beschreibungen zu folgenden
Funktionalitäten aus:
• Zugriff auf Raumdatenauswertungen mit verschiedenen Rollen
• Beachten Sie, dass User mit unterschiedlichen Rollen unterschiedliche
Ansichten auf Raumklimadaten haben
• Beachten Sie, dass zu bestimmten Räumen zu bestimmten Zeiten keine
Messdaten vorhanden sein können (z.B. Datenschutz)
• Use Cases zu Grenzwertwarnungen
• Beachten Sie, dass hier u.U. Entscheidungen zur Umsetzung getroffen werden
müssen, die nicht in der Aufgabenstellung spezifiziert sind
• Achten Sie darauf, dass die Use Case Beschreibungen im Einklang mit
allen anderen Inhalten des Softwarekonzeptes stehen (z.B. Use Cases
vs. GUI Prototyp)
