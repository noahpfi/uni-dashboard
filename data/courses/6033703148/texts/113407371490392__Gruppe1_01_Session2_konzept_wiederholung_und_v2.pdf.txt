Softwarekonzept – Systemüberblick
• Zielsetzung
• Zielgruppe
• Benutzer
• Funktionalitäten
• Fassen Sie die Aufgabenstellung und Ihre Interpretation
dieser kompakt in eigenen Worten zusammen
• Beschreiben Sie Ihr Gesamtkonzept der geforderten
Software
• Verzichten Sie auf Kopieren von Textpassagen oder Sätzen
aus der Aufgabenstellung!
PS Software Engineering I Sommersemester 2026 Page 8
Softwarekonzept – Use Case Diagramm
• Fragestellungen, die Sie in Ihrem Konzept unbedingt
beachten sollten und teilweise direkt aus der Aufgabenstellung
herauszulesen sind:
• Wer darf welche Messdaten einsehen?
• Welche User sehen welche Grenzwertüberschreitungen und in welcher
Form?
• Welche User gibt es im System und wie stehen sie zueinander?
• Wie funktioniert die Geräte-Administration und wer hat Zugriff darauf?
• etc.
• Beschreiben Sie Akteure und Benutzer-Rollen kurz und prägnant
• Achten Sie darauf, dass das Use Case Diagramm im Einklang mit
allen anderen Inhalten des Softwarekonzeptes stehen (z.B. Use
Cases vs. GUI Prototyp)
PS Software Engineering I Sommersemester 2026 Page 9
Softwarekonzept – Use Case Beschreibungen
• Formulieren Sie detaillierter Use Case Beschreibungen zu
folgenden Funktionalitäten aus:
• Zugriff auf Raumdatenauswertungen mit verschiedenen Rollen
• Beachten Sie, das User mit unterschiedlichen Rollen unterschiedliche
Ansichten auf Raumklimadaten haben
• Beachten Sie, dass zu bestimmten Räumen zu bestimmten Zeiten keine
Messdaten vorhanden sein können (z.B. Datenschutz)
• Usecases zu Grenzwertwarnungen
• Beachten Sie, dass hier u.U. Entscheidungen zur Umsetzung
getroffen werden müssen, die nicht in der Aufgabenstellung
spezifiziert sind
• Achten Sie darauf, dass die Use Case Beschreibungen im Einklang
mit allen anderen Inhalten des Softwarekonzeptes stehen (z.B.
Use Cases vs. GUI Prototyp)

Softwarekonzept – Klassendiagramm V1
• Entwickeln Sie ein fachliches Klassendiagramm
• Beschreiben Sie alle Klassen und deren Aufgaben (inkl.

• Planen Sie auch das Löschen einzelner Daten in Ihre
Überlegungen mit ein!

allen anderen Inhalten des Softwarekonzeptes stehen
(z.B. Use Cases vs. GUI Prototyp)

PS Software Engineering I Sommersemester 2026 Page 16
Softwarekonzept – SW-Architektur: Laufzeitsicht
• Entwickeln Sie Sequenzdiagramme für die in der
Aufgabenstellung beschriebenen Kommunikationsabläufe
zwischen den einzelnen Systemteilen
• Mindestanforderung
• Grenzwertverletzung: gesamtes System beachten, d.h. sowohl Arduino als
auch Webapp. User-Interaktion, Grenzwertberechnung,
Grenzwertwarnung etc. modellieren. Bedenken Sie auch, dass die
Grenzwertwarnung nach geeigneten Kriterien wieder ausgeschaltet
werden soll.
• Belegungs-Mindestgrenze: Überlegen Sie sich, unter welchen Umständen
die Belegungs-Mindestgrenze temporär unterschritten werden kann. Und
wie das System weiß, an welchen Tagen Daten am Raspberry nur zur
Grenzwertberechnung verwendet werden dürfen.
• Verbindungsaufbau und –konfiguration Arduino / Raspberry / Webapp.
Von der Erstellung in der Webapp bis zur erfolgreichen Verbindung eines
Arduinos mit einem Raspberry

Softwarekonzept – SW-Architektur: Laufzeitsicht
• Überlegen Sie sich, welche Akteure in den jeweiligen
Abläufen beteiligt sind
• Überlegen Sie sich alle möglichen Abläufe und Alternativen
und treffen Sie wo nötig Designentscheidungen
• Dokumentieren Sie alle Designentscheidungen
• Beschreiben Sie die modellierten Abläufe kurz textuell
• Achten Sie darauf, das die Sequenzdiagramme in Einklang
sind mit (z.B. Bezeichnung):
• Aufgabenstellung
• Klassen- und Use Case Diagramm
• API Dokumentationen
PS Software Engineering I Sommersemester 2026 Page 18
Softwarekonzept – REST API Dokumentation
• Dokumentieren Sie die REST APIs beider Server im System
• Webapp (Frontend und Raspberry)
• Raspberry (Minimale API)
• Überlegen Sie sich für jeden Endpoint: HTTP-Method, Pfad, Request-
/Response-Formate, Fehlercodes, und DTOs
• Siehe Vorlage im Skeleton-Wiki, bzw. alternativ: Excel File im Skeleton
Repository
• Wichtig: Je genauer Sie hier arbeiten, desto leichter wird das
unabhängige Arbeiten von z.B. Raspberry-Team, Frontend-Team und
Backend-Team
• Achten Sie darauf, das die Sequenzdiagramme in Einklang sind mit (z.B.
Bezeichnung):
• Aufgabenstellung
• Klassen- und Use Case Diagramm
• API Dokumentationen
PS Software Engineering I Sommersemester 2026 Page 19
Softwarekonzept – Lösungsansätze komplexe
Abläufe
• Die erforderlichen Sequenzdiagramme bilden nur einen Teil
der komplexen Abläufe zwischen den einzelnen
Komponenten ab
• Diskutieren Sie im Team weitere in der Aufgabenstellung
beschriebene komplexe Abläufe und Funktionalitäten
• z.B.
o Messdatenerfassung am Arduino: Messintervalle, Aufbereitung und
Aggregation Daten, Übertragung Raspberry Pi
o Grenzwertverletzungen: Umgang mit Ausreißern bei Berechnung;
Änderungen der Grenzwerte - Auswirkungen auf historische Daten
o Anzeige von Grenzwertverletzungen in Webapp: Anzeigedauer?
Deaktivierung möglich?

Softwarekonzept – Lösungsansätze komplexe
Abläufe
• Formulieren Sie Ihre Lösungsansätze textuell aus
• Verwenden Sie Modellierungsansätze wo angebracht
• Weitere Sequenzdiagramme
• Zustandsdiagramme
• Klassendiagramme
• Bedenken Sie auch mögliche nicht explizit in der Aufgabenstellung
beschriebene Funktionalitäten wie z.B. Löschvorgänge
• Dokumentieren Sie alle getroffenen Designentscheidungen
• Achten Sie darauf, dass Ihre Lösungsansätze im Einklang mit dem
restlichen Softwarekonzept sind:
• Aufgabenstellung
• Klassen- und Use Case Diagramm
• Laufzeitsicht
• API Dokumentation
• etc.

Softwarekonzept – Ausfallssicherheit
• Entwickeln Sie Ansätze um die Ausfallssicherheit des Systems zu
gewährleisten
• Überlegen Sie sich zu geforderten Punkten 1 – 5 im Anforderungsdokument
worauf geachtet werden muss hinsichtlich:
• Datenkonsistenz
• Logging
• Wiederaufnahme des Betriebs
• Informationsaustausch zwischen den Komponenten
• Informationen für User (rollenabhängig)
• Formulieren Sie zu den geforderten Punkten 1 – 5 Ihre Lösungsansätze aus
• Textuelle Beschreibung verpflichtend
• Unterstützung durch Modellierungen erwünscht
• Achten Sie darauf, dass Ihre Lösungsansätze im Einklang mit dem restlichen
Softwarekonzept sind:
• Klassen- und Use Case Diagramm
• Laufzeitsicht
• API Dokumentation
• etc.
